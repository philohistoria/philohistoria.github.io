Turn your analysis into a website or app · do it on the right

What building means here

  • An analysis that only you can run is one nobody else can use.
  • Building means turning your analysis into a website or an app that other people can use:
    • a webpage that shows your results and lets people click through them
    • one command that reruns your whole analysis, from raw data to finished tables
    • a small app that does a repeated chore for you
  • The division of labor is the same as Monday. You specify and verify, and the agent writes the code.

How a web page works

  • Every webpage, from a personal site to a results page, has three layers:
    • what the reader sees, which is the structure, the style, and the behavior
    • what changes on the page, which is the inputs and filters
    • where the numbers come from, which is your analysis output
  • You will let the agent write all of these layers.
  • You need to know the layers so you can check the agent's work. Open the page, click through it, and verify the numbers against your output.

Keeping private data on your own machine · do it on the right

When your data cannot leave your computer

  • Some data cannot be sent to a company's servers, such as human subjects, restricted records, and anything under an IRB or a data agreement.
  • The default tools send your files to Anthropic or OpenAI, so for that data you cannot use them.
  • The fix is to run the tool on an open-source model on your own machine, so nothing leaves it.

How to keep it local

  • Ollama is a free program that runs open-source models such as Llama or Qwen on your laptop.
  • You can run Codex against a local model with codex --oss, or point Claude Code at it with three settings: ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN, and ANTHROPIC_MODEL.
  • You set the sandbox to your project folder and turn the network off.
  • Local models are slower and weaker than Claude or GPT, so you use them only when the data requires it.

Who splits the work?

  • Today's capstone fit in one conversation, and your next real project will not.
  • The design question that follows is decomposition: when a task is too big for one session, who breaks it into pieces, you or the agent?
  • Both agents cover the full range:
    • You decompose fully. A shell loop calls claude -p (Codex: codex exec) once per item on a list you wrote, when you already know every piece.
    • You plan, the agent executes. Plan mode makes it present a plan you approve before it touches a file, when you know the goal and the steps need thought.
    • You frame, the agent splits. "Do A, B, and C in parallel with separate subagents" works when the pieces are independent and summaries are enough, as Thursday's parallel paper reading showed.
    • The agent decomposes fully. A workflow has the agent write an orchestration script that runs dozens of subagents, for a repository-wide audit or a hundred-item migration.

Before you parallelize

  • Four rules of thumb from Anthropic's own multi-agent engineering:
    • Independence. Only subtasks that do not depend on each other's output can run in parallel. A chain of dependent steps gains nothing.
    • Cost. A multi-agent run measures at about 15 times the tokens of a single chat, so the task has to be worth it.
    • Focus. Three agents with sharp, separate briefs beat five with scattered ones.
    • Independent review. A reviewer agent with clean context catches what the author's context has learned to overlook, for the same reason journals use outside referees.

After the five days

Local and open models: how good are they, and why use a second model?

  • How good they are. Small local models in the 7B class drop 15 to 40 points on agentic benchmarks and hallucinate tool calls. Frontier open-weights models such as Kimi K2.6 and Qwen 3.6 sit within a few points of the closed frontier.
  • A second use, cross-model review. BK Lee's academic setup wires /codex and /gemini commands into Claude Code, so a second model family reviews the first's work: "each catches what the others miss."
  • The statistical logic. Error cancellation assumes independent errors, and models from one family make correlated ones. A reviewer from a different family is closer to an independent draw.

Hands-on

Step 1

Choose one to build

Pick one of these and build it in your own repository. You have 100 minutes.

  • A website that shows your results and lets people click through them.
  • One command that reruns your whole analysis, from raw data to finished output.
  • A small app that does a chore for you, like making codebook pages.
  • A smarter agent. Expand your AGENTS.md and add a second Skill.

If you finish early, add a second option.

Step 2

Rules of the build

  • Everything lands in your own repository.
  • Keep the discipline from Tuesday: the agent proposes a plan, you review it, then it builds.
  • Verify first, then polish: check every number on the page against the files in output/.
  • Commit at every working stage, so you can always step back.
Step 3

Suggestions for your choice

  • Website: start from Tuesday's chart, and add one control, such as a country selector or a year slider.
  • One command: chain Tuesday's stages so one command reruns clean, model, and output.
  • Small app: automate the chore you noticed these five days, such as codebook pages, variable labels, or filing output.
  • Smarter agent: write the second Skill you wished you had, and close any gaps you found in your AGENTS.md.

A starter prompt for the website option:

Build a webpage that shows the chart in output/. Add one control, a country selector, that filters the chart. Show me a plan first, then build it. Do not change my analysis code.copy
Commit before each big change, so you can step back to a working stage if something breaks.
Step 1

Install a local model

Install Ollama, then pull an open-source model to your machine.

curl -fsSL https://ollama.com/install.sh | shcopy
ollama pull qwen3copy
Step 2

Point your agent at it

For Claude Code, set the three settings so it talks to the local model instead of the company's servers. Ask the agent for the exact values for your model.

export ANTHROPIC_BASE_URL=... export ANTHROPIC_AUTH_TOKEN=... export ANTHROPIC_MODEL=...copy
  • For Codex: codex --oss starts it against the local model instead.
  • Set the sandbox to your project folder with the network turned off.
Step 3

Check that nothing leaves

  • On ordinary data first, ask the local agent a question with the network off.
  • Turn off your wifi and give it a task. If it still works, nothing was going out.
  • This is the proof you can show an IRB: the data stayed on the machine.

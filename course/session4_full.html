Agent capabilities

What it can and cannot touch

  • The agent works only with what it can reach:
    • your files and your code: always
    • the open web: often
    • Connect your library databases, your Zotero, and journal APIs, and this only works once you connect them.
  • You can reach an outside app in two ways. You can connect it once with MCP or let the agent operate it by clicking. This is called computer use.

Connecting to other apps (MCP)

  • You connect an outside app once, and then the agent can use it, and MCP is the standard for that connection.
  • Everyday examples include Gmail, Google Calendar, and Google Drive, which are not programming tools, and once connected, the agent can act on them directly. For example: "find the reviewer’s email about the deadline and put the date in my calendar."
  • The research example is Zotero, and you will watch it live in the literature part of this session.

Computer use

  • Some sources lack an API and a connector, and you can only access them by clicking through a website. For example, a statistical yearbook site might hide each table behind three menus and a download button.
  • A computer-use agent acts like you. It takes a screenshot, moves the mouse, types, and clicks.
  • Codex has this built in now, and it can drive a browser and control your desktop apps.
  • Claude Code does not have it yet, and Anthropic's version is a separate Chrome extension.

When computer use is worth it

  • It is a government or survey portal which has no API. You must set filters and download a file by hand.
  • You describe the goal. It clicks through the portal and pulls the file.
  • Use it only if an API or a script fails to do the job.

The limits of computer use

  • It is slow and works one screenshot at a time.
  • It is unreliable for long click-throughs and spends your usage fast.
  • Text on a page can trick it, and it might follow instructions from the text. Never point it at sensitive information.

The two services we use

  • We use two services for literature work:
    • OpenAlex. A free, open index of more than 250 million scholarly works you can search by topic, citation, or metadata.
    • Zotero. Your own library, which the agent can read after you connect it.
  • The steps are simple. Find papers by topic, filter them, follow their citations, and export the kept papers to Zotero. The agent reads your library while you write.

Collecting data with the agent · do it on the right

Data Collection Capabilities

  • The agent can use that same reach to get data.
  • Three common sources, and the agent handles all three:
    • a web page with a table you want, such as a state agency's statistics page
    • An API returns data, which includes the Census or a city open-data portal.
    • Download and unpack a file, for example, a CSV inside a ZIP.
  • You still choose the source, choose the variables, and decide the amount.

Verify your collection

  • These agents are weakest at gathering data.
  • Agents used a social-science replication benchmark and scored about 96 running an analysis and about 31 finding the data it needed.
  • Scrapes will break and fields will be wrong, so check every pull against the source.

Nguyen et al., "ReplicatorBench" (2026), arXiv:2602.11354.

Example: pulling from an API

  • Say what you want in simple words: "Get county population from the Census API for my state, 2010 to 2020, as a CSV."
  • The agent writes the request, runs the request, and shows you the first rows.
  • If the API requires a free key, paste your key in once and it will use it from then on.
  • Read the columns and confirm they are the ones you asked for.

Scraping a table from a webpage

  • Point it at the page and "Get the monthly unemployment table from this URL and put it in a CSV."
  • The agent reads the page, finds the table, and saves it.
  • Watch for the problems it should flag: a table split across pages, footnotes mixed into cells, and a site that asks you not to scrape.
  • If a site's terms forbid scraping, stop and find another source.

Track raw pull sources

  • Please paste the text you'd like me to rewrite.
  • The agent must write the source next to the file and must also write the date and the exact query next to the file.
  • Months later, you use that note to answer "where did this number come from."

Check your results

  • Open the raw file and read the first few rows yourself.
  • Manually compare some values against the source page or the API.
  • Match the data first and Then move it into your analysis.

Turn Repetition into a Skill

  • You repeat a pull, and for example, you grab this month's new records, and this is worth packaging.
  • I don’t have the source text yet — please paste the text you want me to rewrite and I will follow your instructions exactly.

Scaling a pull: script or subagents?

  • One question matters: are the steps the same for every piece?
  • It is the same and it is 50 calls to one API. Each call has a different state code and this is a loop in a script and no agent is needed.
  • Every piece is different, and there are 10 state websites, and each one has its own layout. This is subagent work, and each copy must figure out its own page.

Using subagents for reading

  • Subagents follow Tuesday's arrangement and one main agent delegates tasks to helpers. Each helper has its own separate context and returns a short report.
  • This separation makes subagents good at reading and each paper's full text stays in its own subagent's context. Five papers run in parallel using five contexts and your conversation receives only the five reports.
Live demo

Reading five papers at once

  • The setup: papers/ has five PDFs about one topic.
  • One prompt sends each paper to a separate subagent:
Read each PDF in papers/ in parallel, using a separate subagent per paper. Each subagent writes notes/<paper>.md with: research question, data, identification strategy, main effect size, and stated limitations. When all notes exist, write notes/synthesis.md comparing the identification strategies and flagging disagreements between papers.
  • The structure is the same five times and you get one note per paper and each note has the same five fields.
Live demo

Why the synthesis step waits

  • Each paper has independent reads, no note needs another note, and all five run at once.
  • The synthesis needs every note and it starts only after the last reader finishes.
  • The design rule is to split the work, run the independent pieces at once, and hold back the step that needs them all.
  • The result is notes/synthesis.md, and if two papers have different effect sizes, the file notes this and includes both numbers.

Subagent Instructions

  • Tuesday's lesson applies again when you delegate to many subagents, and "Read these papers and take notes" is an example which leaves every subagent to invent its own note format.
  • Anthropic released a report in 2025 about its multi-agent research system which found that subagents need clear instructions and, without them, subagents misinterpreted the task, and they also performed the exact same searches as other agents.
  • A workable delegation names three things:
    • Objective. What each note is for: feeding the comparison.
    • Output format. There are five named fields and they are in a named file.
    • Boundary. Each person gets one paper and no agent touches another person's file.
  • The demo prompt is long, and it states all three, and each clause closes one of these failures.

Parallelization: what and how much it costs

Runs in parallelMust stay sequential
one paper per subagentcleaning before modeling
one specification per agentsynthesis after reading
  • Independent pieces work at the same time, but steps that share state or feed each other do not.
  • The cost. Anthropic measures multi-agent runs, and they use about 15 times the tokens of one chat. Parallelism gives you speed and a clean context, and it costs more.
  • This same pattern works for robustness checks in later projects. Use one subagent per specification, and each subagent returns one coefficient row, and this creates a single comparison table.

Discussion

Where are the lines?

  • If by "your field" you mean mine (an AI writing assistant), legitimate AI help includes: - Drafting and editing for grammar, clarity, tone, concision, structure, and formatting. - Brainstorming outlines, section headings, angles, hooks, or topic lists. - Summarizing long documents, extracting key points, or condensing material. - Translating text or simplifying language for accessibility or different reading levels. - Generating templates (emails, cover letters, reports) and example phrasing you can adapt. - Producing code comments, documentation, and example snippets for software projects. - Assisting with citation formatting and locating likely sources (but verifying accuracy yourself). - Creating patient- or client-facing explanatory materials or plain-language summaries that a qualified professional must review. - Rewriting or polishing copy for journalism or marketing, with strict fact-checking and disclosure as needed. Where AI help is not or requires caution: - Don’t present AI-generated substantive ideas or analyses as your sole, undisclosed authorship in academic work; follow your institution’s rules about disclosure. - Don’t rely on AI for legal or medical advice without review by a licensed professional. - Avoid submitting AI outputs in closed-book exams, assignments that ban outside help, or where doing so would breach policy or contract. - Don’t provide confidential, proprietary, or sensitive personal data (e.g., PHI) to the model. Practical rules to follow: - Verify facts, citations, and technical claims before using them. - Disclose AI assistance when required by your institution, publisher, or employer. - Use AI as a drafting and editing tool, not as a substitute for expert judgment or final approval. If you tell me which specific field you mean (academic research, journalism, law, medicine, software, etc.), I can give more tailored guidance.

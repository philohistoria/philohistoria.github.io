Reading discussion

Read before class

Does the tool actually help? Two evaluations

  • Dell'Acqua et al., "Navigating the Jagged Technological Frontier" (Harvard Business School Working Paper 24-013, 2023). A randomized experiment with 758 BCG consultants: AI raised speed and quality on tasks inside its competence, and made people more wrong on a task designed to sit just outside it.
  • UK Department for Business and Trade, "Evaluation of the M365 Copilot Pilot" (2025), executive summary. A government ministry's own evaluation: real but small time savings, hallucinations observed throughout, and no evidence that saved time became higher productivity.
  • Optional:
    • Brynjolfsson, Mitchell & Rock, "What Can Machines Learn, and What Does It Mean for Occupations and the Economy?" (AEA Papers & Proceedings, 2018), the pre-agent task rubric.
    • GAO, "Generative AI Use and Management at Federal Agencies" (GAO-25-107653).
    • "Generative AI in Public Administration: A Quasi-Experimental Analysis of Bureaucratic Productivity" (Government Information Quarterly, 2026).

Discussion (~20 min)

  • Dell'Acqua's consultants did worse with AI on a task chosen to sit just outside its competence. Which task in the job you want has that shape?
  • The DBT evaluation found time savings but no productivity gain, and Pennsylvania-style pilots report large self-reported savings. An agency asks you whether to buy licences for 5,000 staff: which evidence do you use?
  • Both studies tested chat assistants, not agents like the one you are using. What in these findings still applies, and what needs re-testing?

Your repository · do it on the right

Git in fifteen minutes, agent-first

  • Git keeps a history of your project: a commit is a labeled snapshot you can always go back to.
  • A folder with this history is a repository.
  • You will not type git commands from memory. The agent runs them; your job is to read what it did.
  • Why bother during shopping period: every deliverable in this course is "committed to your repository," starting Week 3.
  • Why it matters for policy work: a memo's numbers should be traceable to the exact version of the code that made them. The history is the paper trail.

One project, one folder

  • Everything in this course lives in one folder, and the agent works inside it.
  • Ask the agent for a clear layout, so you and it always know where things are:
README.mdwhat this project is
data/your data
scripts/analysis code
output/tables, charts, and later your public page

Directing the agent · do it on the right

Three ways to run the agent

  • The agent runs at one of three levels of freedom:
ModeWhat it can doBest for
Plan modelooks and proposes; changes nothingthinking first
Normaledits and runs, asking as it goesday-to-day work
Auto-acceptedits and runs without askingtrusted, repeat work
  • Ask yourself how much you would let a brand-new intern do unsupervised; that is how to pick the mode.

Plan mode is the one to learn

  • In plan mode the agent reads your project and writes a plan: the steps it intends to take, before it takes any.
  • You read the plan, change what you disagree with, and only then let it run.
  • A wrong plan costs one rewrite. A wrong execution costs an afternoon.
  • The habit for any multi-step task in this course: plan first, then run.
Live demo

Take 1: the vague prompt

Analyze the 311 data and tell me what this city's biggest problems are.
  • What comes back looks like an answer:
    • It runs, and it produces something plausible.
    • Which categories did it merge? What time window? Did it adjust for neighborhood population? You cannot tell without reading the code.
  • It looks plausible, and you cannot check any of it. That is the kind of output that should not go into a policy memo.
Live demo

Take 2: the same task, directed

  • Explore: "Look at the 311 file. What category and date fields are there, and how messy are they?"
  • Plan: "Propose an analysis of complaint patterns by neighborhood. State the time window, how you will handle duplicate reports, and whether counts are adjusted for population."
  • Review the plan, and change one thing you disagree with.
  • Execute step by step, committing after each step.
  • The output looks similar; the difference is that you made every choice.

What a session costs

The agent bills by the token

  • Everything you send and everything it writes is counted in tokens, and your plan has a limit.
  • A long session, a big file pasted in, or many rounds of back-and-forth all run the count up.
  • This matters here because you are on student budgets: the course is designed to fit a Pro plan, and the habits below are how it fits.

How to spend less

  • Give a tight brief so it gets there in fewer rounds; plan mode is also a cost tool.
  • Start a fresh session for a new task, so it is not re-reading an old one.
  • Point it at just the one file it needs.
  • If you hit your limit before class ends, say so. Do not silently stop working.

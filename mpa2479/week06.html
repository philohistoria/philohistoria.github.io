A typical session uses 10 minutes for previous observations, 25 for demonstration and guided use of agentic AI tools, 75 for practice including a 10-minute break, 30 for project discussion, and 10 to record next steps. We adjust the balance to the task.

Charts for a non-technical reader · do it on the right

The chart and the script

  • The chart is written by a script in scripts/ and saved to output/.
  • Rerun the script to rebuild the chart from the current data.
  • Never edit a chart by hand in an image editor. A hand-edited chart cannot be reproduced.
  • Give your intended reader three things:
    • axes with units, so the numbers have meaning,
    • a caption in plain language saying what the chart shows,
    • the source and the date of the data.
  • Ask the agent for the chart, then read the script it wrote. The choices are in the script: which rows were dropped, how categories were merged, what the denominator is.

What you are charting

  • Use your project data, the Our World in Data life expectancy series, or the Federal Register records you collected in Week 4.
  • If your Week 5 measure came from your own text, use that measure too.
  • One figure, with a caption in plain language stating the finding and the audience.
  • If you use a coded measure, explain its source and what the Week 5 evaluation established about its errors.

The results page · do it on the right

An HTML results page

  • The build is one HTML page presenting this week's analysis. It has three parts:
    • your policy question, in one sentence,
    • one figure or one table taken from your pipeline's output,
    • one sentence saying what you found.
  • Commit the page with the scripts and figure in your GitHub repository.
  • The figure on the page is the file the script wrote. Do not paste a screenshot.
  • If you finish early:
    • add one control that filters the chart, such as a geography selector or a year slider,
    • then add a second page for a second result, with a link between the two pages.

Hallucination and source checks · do it on the right

Check the explanation before publishing

  • Hallucination is AI-generated content that is false or unsupported by the available evidence. A fluent explanation can misstate a number, invent a source, or add a claim the analysis never tested.
  • Choose two claims from the agent’s explanation or caption. Trace each one to script output or an original source.
  • Check the year, units, denominator, and meaning of the claim. For a citation, open the source and locate the relevant passage.
  • Record whether the evidence supports the claim, contradicts it, or leaves it unresolved. Revise the explanation before it goes on the page.

Publishing on GitHub Pages · do it on the right

From a page to a public URL

  • GitHub Pages publishes your HTML results page at a web address.
  • Anyone with the address can open the page. No login and no account are needed to read it.
  • Check the files that will be published. If you make the GitHub repository public, also review its tracked files and history.
  • Record the public link in the README of your GitHub repository.
  • GitHub documentation on creating a GitHub Pages site →

What the URL is for

  • A reader can inspect evidence that is published at an address they can open. The URL is where that inspection happens for your project.
  • The product you write next cites the page, so the reader can see the figure without you sending them a file.
  • Exchange addresses with another group and give each other feedback on the page in class.
  • Use the figure and explanation to develop the first version of your group’s policy product.

Preliminary results

From the exercise to the policy product

  • Use the HTML exercise to practice presenting a checked finding to a specific reader.
  • For your group project, develop a first product from the group’s own question, evidence, and intended audience.
  • Explain which policy alternatives the finding informs and what further evidence you need.

Project and policy discussion

Findings, alternatives, and communication

  • What does the result establish? What remains unresolved?
  • Which policy alternatives or evaluation criteria does it inform? What additional evidence would you need to project their outcomes?
  • Did AI help you analyze or communicate the result? Show a concrete example.

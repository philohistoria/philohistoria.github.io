Opening

This course

  • Every week has two parts: you build something with an AI agent, and you read and argue about how AI is changing public policy.
  • An agent is AI that writes and runs code on real data, inside a project on your computer.
  • You are not expected to write code from memory. You direct the agent; it writes and runs the code; you judge what comes back.
Live demo

An agent doing a policy analysis

  • Question: what do residents of a city complain about, and where?
  • Data: the city's 311 service-request file, downloaded from its open data portal.
  • I hand the agent a single instruction and let it work:
Using Python: load the 311 service-request file, clean the category and neighborhood fields, count requests by category and by neighborhood, and make one chart of the top complaint categories and one map or chart of requests by neighborhood. Save both as PNGs.

What just happened

  • The agent wrote the code and ran it.
  • It hit errors, read them, and fixed them.
  • It checked its own output.
  • It returned two charts for us to inspect.
  • My only inputs were the instruction at the start and my reading of the charts at the end.

From analyst to director

  • The agent produced the neighborhood counts in about two minutes.
  • Whether those counts mean anything for policy is still a human call: 311 records measure who complains, not what is broken.
  • That division of labor runs through the whole course: the agent does the implementation, and you own the question and the judgment.

Who this course is for

  • You have taken at least one course that used a programming language, ideally Python.
  • You can look at a script and roughly follow what it does, even if you could not write it from scratch.
  • You do not need a computer science background.
  • You need a laptop in every class. This is a hands-on course.

One tool, on purpose

  • This course runs on one coding agent: Claude Code.
  • Every hands-on uses its exact commands, and one setup per person is the only way to support a full room.
  • What you learn transfers: the habits of directing, specifying, and checking work the same in any agent.

The semester at a glance

  • Weeks 1–2: meet the agent and learn to direct it.
  • Weeks 3–7: walk the evidence steps at production depth: define your problem (Step 1), assemble the evidence (Steps 2a–2c: collect, construct, analyze and publish), then verify what the agent produced (Step 2½), a step this course adds to the path.
  • Weeks 8–10: apply the path to AI itself: score a real federal AI system against criteria (Steps 3–4), predict the outcomes of your own proposed tool (Step 5), and weigh and decide how AI should be governed (Steps 6–7).
  • Weeks 11–12: build, and tell your story (Step 8).
  • The first seven weeks are AI for policy: the agent works as your analyst. Weeks 8–10 are policy of AI: AI systems are the thing being governed.
  • By December you will have: a public web page with your analysis, an automated data pipeline, a policy brief, a fairness analysis, and an audit of a real government AI system.

What an AI agent is

Isn't this just ChatGPT?

  • Underneath it is the same kind of model. The difference is the machine built around it.
  • Ask ChatGPT for the 311 analysis, and it hands you a block of code to run yourself.
  • Give the agent the same request, and it writes the code, runs it, hits an error, and fixes it, until the charts exist.
  • ChatGPT answers once and stops. The agent keeps working until the task is done.

It works in a folder, not a chat

  • You pick one folder for your project, and the agent works inside it.
  • Your data, your scripts, and your outputs are all in there together.
  • The agent only touches things in that folder, so it stays out of the rest of your computer.
  • Its notes stay in the folder, so next session it picks up where you left off instead of starting over.

Condition 1: tool use

  • A language model on its own only produces text.
  • Tool use gives it real actions: read a file, write a file, run a command, search the web.
  • Every time it edits a script or runs python analysis.py, that is tool use at work.
  • This is why the agent asks permission before it acts: it is running on your machine.

Condition 2: the agent loop

  • A chatbot answers once. An agent works in a loop until the goal is met.
  • On the 311 charts the loop ran like this:
    • it read the file and found the column names,
    • it wrote code to clean and count the categories,
    • it ran the code and hit an error on inconsistent neighborhood names,
    • it read the error and rewrote that step,
    • it ran again and produced the charts.
  • The loop pauses for your approval, and that pause is where your judgment enters.

Condition 3: running the code

  • Code that has not run is only a guess.
  • The agent runs its own code, reads what breaks, fixes it, and runs again, so you end up with a result that works.
  • Running its own code is what lets the agent finish the job.

The three conditions together

A model aloneAn agent
generates a code snippetwrites, runs, tests, and fixes code
describes what a script should doimplements it and verifies it
suggests an approachexecutes it and iterates to a result
  • Take away any one of the three, and the system falls back to a chatbot.

One warning for the semester

  • These models are built to sound fluent, and fluent language can still be wrong.
  • The case to fear is the answer that is confident and wrong at once. A fabricated statistic in a policy memo looks exactly like a real one.
  • So you check every result the agent gives you, every time.
  • The rule for the semester: an unverified number never goes into a memo.

Setup · do it on the right

What the terminal is

  • The terminal is a text interface to your computer: you type a command, it prints the result.
  • On a Mac it is the app called Terminal; on Windows it is PowerShell.
  • Agents live here because this is where programs are run.
  • You need very little of it: cd folder moves into a folder, ls lists what is there.
  • Everything else you can ask the agent to type for you.

When something breaks

  • Something will break today. That is part of the course, on purpose.
  • When the agent runs a command that fails, it reads the error and fixes it on its own; you watch and steer.
  • When you are stuck yourself, tell the agent in plain words what happened.
  • Raise your hand the moment a step fails. Setup problems are not your fault and not a sign you are behind.

Redo the demo yourself · do it on the right

Same task, your machine

  • You watched the agent do the 311 analysis this morning. Now you run the same task yourself.
  • The dataset and the exact instruction are on the right; the point is to see the loop happen on your own screen.
  • Watch what it does with the instruction: each place where it makes a choice you did not specify is a decision that should have been yours.

If you finish early

  • Try the same kind of task on a second dataset from the portal: building permits, restaurant inspections, or crime incidents.
  • Change the question, not just the file, and see whether the agent's choices still make sense.

Code review and replication

Authors: Han Zhang and Codex (OpenAI)

Use a classmate’s rerun to improve both the project and its explanation.

Opening

Today

  • Read a project through its README, output-producing scripts, and data documentation.
  • Use the rest of the session for replication, feedback, and revision.

Reading code you did not write

What to open first

  • Open the group’s GitHub repository. Read the README, the scripts that produce the results, and the data documentation.
  • Identify the policy question, the expected outputs, and the documented commands.
  • In Week 4 you reran a classmate’s data pipeline. Today you will check the analysis and its policy conclusions as well.

Reviewing with agentic AI tools

Read this GitHub repository. Describe the policy question, the expected outputs, and the steps needed to reproduce the results. Identify the scripts and sources supporting the main finding.

Check the agent’s summary against the files, then run the documented commands. In the terminal, type each command yourself. In the app, ask the agent to run the documented commands and show the output.

Diagnosing a failed rerun

  • Record the failing command and its error message.
  • Check for missing files, machine-specific paths, undocumented steps, and code errors.
  • Explain the correction needed in the code or instructions.

Replication and peer review · do it on the right

Rerun the project

  • Exchange group GitHub repositories and clone the shared version.
    • In the terminal, run git clone on the other group’s repository.
    • In the app, open a new folder as the project and ask the agent to clone the repository into it.
  • Follow the README and record what ran, what failed, and what information you had to infer.
  • Compare the resulting figures or tables with the group’s reported findings.

Review the policy analysis

  • Identify which findings the evidence supports and which claims need further analysis.
  • Check how the findings inform the policy alternatives, criteria, and recommendation.
  • Suggest one useful revision to the analysis or its explanation for the intended audience.

Feedback and revision

  • Share brief notes with the authors in class. Point to the relevant command, result, or claim.
  • Use the feedback on your own group’s work to correct the code, documentation, or policy product.
  • Rerun the affected analysis and commit the revisions to the group GitHub repository.

Project and policy discussion

Replication and revision

  • Can another analyst reproduce the result and understand the choices behind it?
  • What did the agent help diagnose or repair?
  • Which part of the analysis or recommendation still needs attention?

Assignments

Weekly memo · due Dec 10 before class. Write 1–2 observations from your project or the classroom case: the policy-analysis step you attempted, how AI helped or fell short, and what you would do next. Aim for 150–200 words total. Describe what you actually tried and observed in your own words. Do not use AI to write the memo. Begin in class and submit to Canvas Discussions. See memo grading.

Next class

Use the review to prepare your group’s final presentation for Dec 10.

Hands-on

Step 1

Exchange GitHub repositories

Share a committed version of your group’s project. Clone another group’s GitHub repository into a new folder. In the terminal, run git clone. In the app, open the new folder as the project and ask the agent to clone the repository into it.

Step 2

Read and rerun

  • Read the README, output-producing scripts, and data documentation.
  • Follow the documented commands. In the terminal, type them yourself. In the app, ask the agent to run them and show the output.
  • Record the step and error when a command fails.
  • Note any information you had to infer or ask the authors to clarify.
Step 3

Check the finding and policy implications

  • Compare the reproduced outputs with the reported finding.
  • Check the evidence for the policy alternatives and recommendation.
  • Identify one claim or comparison that needs revision.
Step 4

Share feedback in class

Give the authors brief notes on the rerun, supported findings, and a useful revision. Discuss the specific result or passage behind each point.

Step 5

Revise your own project

Address the feedback your group received. Rerun the affected analysis, check the revised explanation, and commit the changes.
